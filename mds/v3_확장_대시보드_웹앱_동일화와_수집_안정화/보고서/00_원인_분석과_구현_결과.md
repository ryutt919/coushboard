## 요약
- 확장 대시보드를 웹앱과 **같은 React 코드(`src/`)로 빌드**했다. 저장소만 Supabase에서 `chrome.storage.local` 로 바꿨고, 로그인과 예시 화면만 없다. 웹앱의 기존 E2E 시나리오 15개가 확장 대시보드에서 그대로 통과한다
- 이중 수집의 **실제 원인**을 재현해 찾았다: 팝업을 다시 열면 진행 상태가 비어 있어 새로 시작할 수 있었고, 두 수집이 어댑터의 모듈 전역 상태를 공유해 서로의 페이지를 덮어썼다. 수집 상태를 저장소에 두고, 한 번에 하나만 돌리고, 페이지마다 저장하고, 이어서 수집하도록 고쳤다
- 사용자의 실제 CSV를 확장 대시보드에 올린 결과가 웹앱 계산과 모든 합계에서 같다
- 실제 쿠팡 로그인 세션에서 확장을 새로 고친 뒤 수집하는 실행은 사용자 Chrome에서 해야 한다(M7)

## 문제 1. 대시보드가 웹앱과 달랐다
- 원인: 첫 버전 확장이 대시보드를 별도 JS로 다시 만들었다(`dashboard.js`, `lib/pipeline.js`). 웹앱의 분류 규칙, 중복 처리, 카테고리 정리, 세부 내역, 업로드 형식 호환을 갖추지 못했다
- 해결: 별도 구현을 모두 지우고 웹앱 코드를 그대로 쓴다
  - `Backend` 인터페이스(`src/lib/backend.ts`)에 `ChromeBackend`(`src/lib/chromeBackend.ts`)를 추가. 설정(규칙, 지정, 합치기, 중복 처리)은 `settings` 키, 주문, 영수증, 가져오기 이력은 background 의 한 줄 대기열을 거쳐 저장
  - `src/state/AppState.tsx`: 확장 빌드(`VITE_TARGET=extension`)면 로그인 없이 `ChromeBackend` 로 시작하고, 저장소가 바뀌면 조용히 다시 읽는다(수집 중 화면 갱신)
  - `src/components/Layout.tsx`: 확장에서는 로그아웃 버튼을 빼고 "쿠팡에서 가져오기" 막대(`src/extension/CollectBar.tsx`)를 넣는다. 저장 위치 안내 문구만 확장용으로 바꿨다
  - `vite.extension.config.ts`: `extension.html`, `popup.html` 을 `coupang-ledger-ext/app/` 로 빌드(`npm run build:ext`). Supabase는 스텁으로 대체
  - 팝업도 같은 빌드(`src/extension/popup.ts`)
- 행 모양: 수집 행을 웹앱의 `OrderRow`(order_no, seq, ordered_at, bundle_no, product_no, status, raw_name, qty, list_price, sale_price, seller)로 만든다. 19자리 묶음배송번호는 JSON.parse 전에 문자열로 바꿔 보존
- 중복 처리: 첫 인수인계서의 "수집 행에는 중복 제거를 적용하지 않는다"는 규칙은 폐기했다. 웹앱과 기능이 같아야 하므로 CSV와 같이 웹앱의 중복 처리(기본 제외, 카테고리 정리에서 복원)를 적용한다. 같은 상품 두 줄은 웹앱과 같이 하나로 보이되 사용자가 되살릴 수 있다(결정 D16)
- 검증(웹앱과 같은 기능)
  - 웹앱 E2E `tests/e2e/demo.spec.ts`, `user.spec.ts` 를 `E2E_MODE=extension` 으로 확장 대시보드에 그대로 실행: **15개 통과**, 3개는 확장에 없는 기능(로그인 화면, 로그아웃 후 새 브라우저 접근, 예시 화면 끝내기)이라 건너뜀. 키보드 조작 시나리오는 예시 버튼 대신 데이터를 넣고 시작하도록 맞춰 확장에서도 실행. 접근성(axe)과 네트워크 호스트 검사 포함(확장 자기 자신 외 요청 없음)
  - 실제 CSV 760행을 확장 대시보드에 올려 웹앱 계산(`prepareRows`, `summarize`)과 비교: 원본 760행, 중복 제거 32행, 받은 상품 5,243,680원, 전체 16,515,529원, 반품과 취소 11,271,849원, 2024 1,491,830원, 2025 2,415,680원, 2026 1,234,150원 **모두 일치**

## 문제 2. 팝업을 닫으면 멈춘 것처럼 보이고, 다시 시작하면 이중 수집
- 재현(합성 쿠팡 응답, Playwright Chromium에 확장 로드)
  - 팝업을 닫아도 콘텐츠 스크립트의 수집 자체는 계속 돌았다. 그러나 진행 상태가 팝업 메모리에만 있어 다시 열면 비어 있고 중단 버튼도 없다 -> 멈춘 것으로 보인다
  - 이때 "수집 시작"을 누르면 두 번째 수집이 겹쳐 시작되었다: 요청 7번이면 될 것이 9번 이상
  - 두 수집이 어댑터의 모듈 전역 상태(`year`, `api`, `pageIndex`)를 공유해 서로의 페이지를 덮어썼다: 저장 18줄 중 서로 다른 (주문, 상품)은 14개뿐(중복과 누락)
  - 행은 수집이 끝난 뒤 한 번에 저장해 중간에 끊기면 모두 사라졌고, 다시 시작하면 처음부터였다
- 해결
  - 어댑터는 수집마다 `createAdapter()` 로 새로 만든다(모듈 전역 상태 제거)
  - 수집 상태를 `chrome.storage.local` 의 `collect` 키에 둔다(상태, 연도, 페이지, 이번에 저장한 행, 연도별 합계, 체크포인트). 팝업과 대시보드는 읽기만 하므로 닫았다 열어도 진행이 이어서 보인다
  - 한 번에 하나만: 콘텐츠 스크립트가 시작 전에 자리부터 잡고(await 앞), 다른 탭이나 최근 갱신된 running 상태가 있으면 거절. background 도 이중으로 거절. 팝업에서는 수집 중에 시작 버튼이 사라진다
  - 페이지마다 저장: 읽을 때마다 background 대기열로 주문 단위 교체 저장하고 체크포인트를 기록. 저장 실패는 삼키지 않고 즉시 멈춘다
  - 이어서 수집: 중단, 오류, 탭 닫힘 모두 체크포인트가 남아 "이어서 수집"이 그 페이지(이미 저장한 마지막 페이지를 한 번 더 읽음)부터 이어 간다. 주문 단위 교체라 겹쳐도 중복되지 않는다. "처음부터 다시"도 선택 가능
  - 갱신이 30초 넘게 끊긴 running 은 중단됨으로 보인다(탭 닫기, 이동)
  - 스크립트가 없는 탭(확장 설치 전에 열린 탭)에는 background 가 스크립트를 넣고 시작한다. 같은 탭에 중복으로 들어와도 살아 있는 인스턴스 하나만 둔다
  - 첫 버전이 저장한 옛 모양의 행은 첫 저장 요청 때 새 모양으로 바꾼다
- 검증(E2E, `tests/e2e-ext/collect.spec.ts`, 합성 쿠팡 응답 요청 7번 분량)
  - 팝업 수집: 연도 순서, 요청 간격 2초 이상, 저장 행 수, 19자리 묶음배송번호, 대시보드 반영과 접근성
  - 팝업을 닫았다 다시 열기: 진행 표시, 시작 버튼 숨김, 별도 시작 요청 거절, 최종 요청 수 7번(겹침 없음), 중복 없음
  - 중단 후 이어서: 2025년으로 넘어간 뒤 중단, 이어서 시 2026년은 다시 가져오지 않고 저장한 페이지부터, 중복 없음
  - 429 오류: 1회 요청 후 중단, 저장한 것은 남고, 이어서 수집으로 마무리
  - 쿠팡 탭 닫기: 끊긴 것으로 표시, 새 탭에서 이어서 수집
  - CSV로 올린 같은 주문과 겹침, 두 번 수집해도 늘지 않음
  - 같은 탭에 스크립트가 또 들어와도 한 번만 수집, 옛 모양 행 변환

## 실행하지 못한 것, 한계
- 사용자 Chrome에서 확장을 새로 고친 뒤의 실제 쿠팡 수집(M7). 확장을 새로 고쳤을 때 죽은 옛 스크립트가 남은 탭은 Playwright의 Chromium에서 `chrome.runtime.reload()` 가 다시 로드되지 않아 재현하지 못했다. 방어 코드(죽은 인스턴스는 무시하고 새로 시작)는 있으나 실제 Chrome에서 확인이 필요하다. 확장을 새로 고친 뒤 쿠팡 탭도 새로 고치면 문제 없다
- 수집 행의 `seq` 는 API 순서이고 CSV의 파일 순서와 다를 수 있어, 같은 주문을 CSV와 수집으로 모두 넣으면 행별 지정(`order_no:seq`)이 어긋날 수 있다. 같은 주문은 나중에 들어온 쪽으로 통째로 교체된다
- 쿠팡 목록에서 사라진 주문(예: 삭제한 주문)은 저장소에 남는다. 수집은 주문을 지우지 않는다
- `coupang-ledger-ext/app/` 는 빌드 결과(폰트 포함 약 11MB)라 커밋하지 않는다. 설치할 때 `npm run build:ext` 가 필요하다
