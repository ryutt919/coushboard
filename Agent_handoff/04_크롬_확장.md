# 크롬 확장: coushboard

## Task Metadata
- **Created/updated at**: 2026-10-05 15:55:00 KST
- **Model used**: `claude-sonnet-5-5`
- **User requirements**: Chrome 확장(MV3, 로컬 저장)의 대시보드를 웹앱과 기능이 완전히 같게 하고, 수집 중 팝업을 닫아도 계속되며 다시 시작해도 이중 수집되지 않게 개선, E2E까지 완료. 읽기 전용 GET, 요청 간격 2초 이상, 오류 시 즉시 중단, 검증하지 않은 것은 확정 금지

## Component Status

> 2026-10-05 이관: 이 문서가 다루는 확장 코드는 별도 저장소 [coushboard-extension](https://github.com/ryutt919/coushboard-extension)으로 옮겼고 이 저장소에서는 제거했다. 아래는 이관 시점까지의 이력이며 현재 상태는 그쪽 저장소의 인계 문서를 따른다.

### 대시보드와 팝업 (웹앱 코드 재사용)
- **Current value/logic**: 웹앱 React 코드(`src/`)를 `VITE_TARGET=extension` 으로 빌드해 확장 페이지로 쓴다. 로그인과 예시 화면만 없고 저장소는 `chrome.storage.local`(키 `orders`, `receipts`, `imports`, `settings`, `collect`)
- **Implementation**: `vite.extension.config.ts`(결과 `coupang-ledger-ext/app/`, 커밋 안 함, `npm run build:ext`), `src/lib/chromeBackend.ts`(`Backend` 구현), `src/state/AppState.tsx`(확장이면 `ChromeBackend` 로 시작, 저장소 변경 시 조용히 다시 읽음), `src/components/Layout.tsx`(확장 분기, `CollectBar`), `src/extension/`(`CollectBar`, `useCollect`, `collectState`, `popup.ts`, `chrome.d.ts` 최소 타입), 루트 `extension.html`, `popup.html`
- **Related files**: 보고서 [v3/보고서/00](../mds/v3_확장_대시보드_웹앱_동일화와_수집_안정화/보고서/00_원인_분석과_구현_결과.md)
- **Rationale**: 별도 JS 대시보드는 웹앱과 기능이 달랐다. 같은 코드를 쓰면 기능이 같다. 웹앱 E2E를 `E2E_MODE=extension` 으로 그대로 실행해 확인(15개 통과)

### 저장소 쓰기 (`coupang-ledger-ext/background.js`, `lib/orders.js`)
- **Current value/logic**: 주문, 영수증, 가져오기 이력 변경(`ORDERS_REPLACE`, `IMPORT_ORDERS`, `IMPORT_RECEIPTS`, `ORDERS_SHIPPING`, `DELETE_ALL`)은 서비스 워커의 한 줄 대기열로 처리. 규칙은 웹앱 `stored.ts` 와 같음(같은 주문번호는 주문 단위 교체)
- **Implementation**: 첫 버전이 저장한 옛 모양 행(`dt`, `price`)은 첫 요청 때 `OrderRow` 모양으로 바꿈
- **Rationale**: 수집(콘텐츠 스크립트)과 CSV 가져오기가 겹쳐도 서로 덮어쓰지 않게

### 수집 어댑터 (`coupang-ledger-ext/lib/adapter.js`)
- **Current value/logic**: `mc.coupang.com/ssr/api/myorders/model?requestYear&pageIndex&size=5` 를 same-origin GET. 연도는 페이지의 연도 칩 텍스트(`^20\d\d$`)에서 읽음. 연도 안 `hasNext` = `api.hasNext && api.nextYear === 현재 연도`. **수집마다 `createAdapter()` 로 새로 만든다**(모듈 전역 상태 없음)
- **Implementation**: 행은 `deliveryGroupList[].productList[]` 에서만 생성(취소/반품 묶음은 복제본). 웹앱 `OrderRow`: order_no, seq(주문 안 0부터), ordered_at(`orderedAt`+9h), bundle_no(`shipmentBoxId`, 19자리는 파싱 전에 문자열로), product_no(`vendorItemId`), status, raw_name(`vendorItemName`), qty, list_price(`unitPrice`), sale_price(`discountedUnitPrice`), seller(`vendorName`). 필수 필드 없으면 `UNEXPECTED_SHAPE`, HTTP 오류 `HTTP_n`, 로그인/캡차 `LOGIN_OR_CAPTCHA`, 페이징 불연속 `PAGING_BROKEN` 으로 즉시 중단(재시도 없음)
- **Related files**: `test/adapter.test.mjs`
- **Rationale**: 연도 칩과 페이지 버튼이 해시 클래스 `<div>` 라 DOM 클릭은 쉽게 깨지고, API가 연도 경계를 `nextYear` 로 이어 준다

### 상태 대응 (`mapStatus`)
- **Current value/logic**: 줄 `cancelReturnStatus` RETURN_COMPLETE=반품완료, CANCELED=취소완료. 없으면 배송그룹 `invoiceStatus` FINAL_DELIVERY=배송완료, DELIVERING=배송중. 이 4가지는 CSV 2025년 352줄과 상태별 개수까지 일치(확정). 실제 로그인 세션 전체 수집(761줄)과 CSV 대조에서 2021~2025년 줄 단위 일치
- **Implementation**: 그 외는 `미확인(값)` 으로 남기고 콘솔 경고. 줄의 EXCHANGE_COMPLETE 는 교환완료로 대응하나 2025년에 없어 미검증. 교환 사례는 CSV에서 1줄 반품완료
- **Rationale**: 추측으로 확정하지 않고 눈에 띄게 남김. 결제 직후(ACCEPT/INSTRUCT, 취소 아님) 상태는 CSV 대응을 모름

### 수집 흐름 (`content/collector.js`, `lib/collect.js`, `background.js`, `src/extension/collectState.ts`)
- **Current value/logic**: 상태는 `collect` 키(status, runId, years, year, page, rows, perYear, checkpoint, error, updatedAt). 팝업과 대시보드는 읽기만 하므로 닫았다 열어도 이어서 보이고 수집은 계속된다. 한 번에 하나(콘텐츠 스크립트가 await 앞에서 자리 잡음, 다른 탭이나 30초 안에 갱신된 running 도 거절, background 도 거절). 페이지마다 저장하고 체크포인트 기록. 갱신이 30초 넘게 끊긴 running 은 중단됨으로 본다
- **Implementation**: 이어서 수집은 체크포인트(연도, 페이지)부터(그 페이지는 한 번 더 읽음), 주문 단위 교체라 중복 없음. "처음부터 다시"도 가능. 스크립트가 없는 탭에는 background 가 `chrome.scripting.executeScript` 로 넣고 시작. 같은 탭에 중복으로 들어와도 살아 있는 인스턴스는 하나. 요청 간격 2.2~3.5초
- **Related files**: `tests/e2e-ext/collect.spec.ts`(8개 시나리오), `test/engine.test.mjs`, `tests/unit/chromeBackend.test.ts`
- **Rationale**: 첫 버전은 진행 상태가 팝업 메모리에만 있어 재시작이 겹쳤고, 겹친 수집이 어댑터 전역 상태를 공유해 페이지가 꼬였다(재현: 요청 9번, 18줄 중 고유 14개). 행도 끝에 한 번만 저장해 중간에 끊기면 사라졌다

### 확장 E2E (`playwright.extension.config.ts`, `tests/e2e/fixtures.ts`)
- **Current value/logic**: Playwright Chromium에 확장을 로드. `tests/e2e/demo.spec.ts`, `user.spec.ts` 를 `E2E_MODE=extension` 으로 확장 대시보드에 그대로 실행(예시 데이터는 `scripts/dump-demo.ts` 로 뽑아 저장소에 넣음), 수집 시나리오는 `mc.coupang.com` 요청을 가로채 합성 응답 제공(쿠팡에는 접속하지 않음)
- **Implementation**: `npm run test:e2e:ext`. 사용자 Chrome 에는 폴더 로드와 `chrome-extension://` 열기가 자동화로 불가하고, Playwright Chromium은 쿠팡 로그인이 거절되므로 실제 로그인 세션 실행은 사용자가 해야 한다(PM M7)
- **Related files**: 보고서 v3/00
