# 쿠팡 지출 기록 (Chrome 확장, 로컬 저장)

쿠팡 주문목록을 연도 구분 없이 가져와, 웹앱(coushboard)과 같은 대시보드로 보여 주는 확장입니다. 데이터는 이 브라우저(`chrome.storage.local`)에만 저장하고 서버로는 아무것도 보내지 않습니다.

## 설치
1. 저장소 루트에서 대시보드를 만든다: `npm install` 후 `npm run build:ext` (결과는 `coupang-ledger-ext/app/`, 커밋하지 않음)
2. `chrome://extensions` → 개발자 모드 ON → "압축해제된 확장 프로그램을 로드합니다" → 이 폴더(`coupang-ledger-ext`) 선택
3. 코드를 바꾼 뒤에는 `npm run build:ext` 를 다시 하고 확장 카드의 새로 고침을 누른다. 열려 있던 쿠팡 탭은 새로 고친다

## 쓰는 법
- 팝업(확장 아이콘) 또는 대시보드 위쪽의 "쿠팡에서 가져오기" 막대에서 시작한다. 쿠팡 주문목록 탭이 없으면 새로 연다(로그인은 직접)
- 수집은 쿠팡 탭에서 돌고 진행 상태는 저장소에 남는다. **팝업이나 대시보드를 닫아도 수집은 계속되고**, 다시 열면 진행 상황이 이어서 보인다
- 수집 중에는 새로 시작되지 않는다(겹쳐 시작하면 데이터가 꼬이던 문제를 막음)
- 페이지마다 저장한다. 중단, 오류, 탭 닫힘이 있어도 저장된 곳까지는 남고 "이어서 수집"으로 그 페이지부터 이어 간다. 같은 주문은 주문 단위로 교체되므로 겹쳐도 중복되지 않는다
- 요청은 읽기 전용 GET, 2.2~3.5초 간격. 로그인 풀림, 캡차, 4xx/5xx는 즉시 멈추고 재시도하지 않는다

## 대시보드
웹앱과 같은 화면과 기능이다(개요, 세부 내역, 카테고리 정리, CSV 올리기, 규칙 내보내기/가져오기, 중복 처리). 같은 React 코드(`src/`)를 쓰고 저장소만 `chrome.storage.local` 로 바꿨다. 없는 것은 로그인과 예시 화면뿐이다.

## 구조
| 파일 | 역할 |
|---|---|
| `lib/adapter.js` | 쿠팡 내부 주문 API 호출, 웹앱 `OrderRow` 모양으로 변환. 수집마다 새로 만든다 |
| `lib/collect.js` | 연도×페이지 순회 엔진(페이지마다 저장 콜백, 이어서 하기, 중단) |
| `content/collector.js` | 쿠팡 탭에서 수집 실행, 진행 상태를 `collect` 키에 기록 |
| `background.js` | 저장소 쓰기 한 줄 대기열, 수집 시작과 중단 중계 |
| `lib/orders.js` | 주문 저장 규칙(주문 단위 교체 등) |
| `app/` | 빌드된 대시보드와 팝업(`src/extension`, `vite.extension.config.ts`) |

## 테스트
```
npm run test:ext        # 어댑터, 엔진, 저장 규칙 (node)
npx vitest run          # 웹앱 로직과 ChromeBackend 단위 테스트
npm run test:e2e:ext    # 확장을 Chromium 에 로드해 웹앱 화면 시나리오와 수집 시나리오 실행(쿠팡에는 접속하지 않음)
```
